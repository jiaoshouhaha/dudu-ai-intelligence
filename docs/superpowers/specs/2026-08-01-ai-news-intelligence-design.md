# AI 新闻情报站设计规格

日期：2026-08-01

## 目标

构建一个低成本、个人使用优先的中文 AI 新闻网站。即使用户的电脑处于休眠状态，云端任务仍每小时自动收集全球 AI 信息。网站把英文标题与摘要翻译为中文，并支持分类、搜索、去重和重要度评分；每条内容仅保留原始来源链接，优先采用中国大陆可用的服务。

## 成功标准

- GitHub Actions 每小时自动抓取一次，电脑休眠不影响任务。
- 网站可展示最新新闻、今日头版、趋势主题和评分理由。
- 所有公开新闻卡片都包含中文标题与中文摘要，不混入英文正文。
- 支持分类筛选、搜索、收藏和已读状态，每条内容只提供原文链接。
- 没有模型 API 密钥时仍可通过本地开源翻译模型抓取、翻译、规则评分和展示新闻。
- 配置兼容 OpenAI 协议的国内模型 API 后，可自动生成双语标题、双语摘要和 AI 评分理由。
- 单个来源或单条模型请求失败不会中断整个任务。
- 第一版无需数据库，除可选的模型调用外不产生固定服务成本。

## 架构

系统由四个边界清晰的部分组成：

1. **来源配置与抓取器**：读取 RSS 白名单并标准化条目。
2. **内容处理流水线**：去重、规则评分、可选 AI 增强、结构校验。
3. **静态数据仓库**：按日期保存 JSON 分片，并生成首页索引、搜索索引、趋势和运行状态。
4. **静态网站**：读取生成的数据并提供浏览、筛选、搜索、双语切换及个人本地状态。

GitHub Actions 在每小时第 17 分钟运行抓取流水线。成功后将数据变更提交回默认分支。网站既可在本地运行，也可部署为静态站点。第一版不引入 Supabase 或其他数据库；数据规模超过静态文件合理范围时再迁移。

## 数据流程

1. 并行抓取已启用的 RSS 来源。
2. 提取标题、摘要、作者、发布时间、来源、分类和原文 URL。
3. 清理追踪参数并规范化 URL。
4. 使用规范化 URL、标题相似度和内容指纹识别重复事件。
5. 同一事件保留一个主记录和多个来源引用。
6. 对新事件执行规则评分。
7. 优先使用配置的 AI 服务翻译新事件；没有 API 密钥时使用本地英中翻译模型和缓存。
8. 校验输出结构，按日期写入新闻分片，并重建首页、搜索、趋势和状态文件。

## 数据模型

每条新闻至少包含：

- 唯一事件 ID
- 规范化 URL 与原始 URL
- 来源列表与主来源
- 原始语言
- 中英文标题
- 中英文摘要
- 分类与关键词
- 发布时间与抓取时间
- 1–100 重要度分数
- 重要度评分理由
- 评分模式：`rules` 或 `ai`
- 处理状态与错误信息

数据写入北京时间当天的 `data/news/YYYY-MM-DD.json`。`data/index.json`、`data/search.json` 和 `data/trends.json` 只包含当天新闻，`data/status.json` 提供更新时间和来源健康状态。跨日运行时删除其他日期分片。

## 重要度评分

规则与 AI 评分使用相同维度：

- 来源权威性：25%
- 行业影响范围：25%
- 技术或商业新颖度：20%
- 时效性：15%
- 可验证性与多源印证：15%

AI 响应必须符合固定 JSON Schema，并返回中英文标题、摘要、分类、关键词、分数和理由。最终分数限制在 1–100。没有密钥、达到预算上限或 API 失败时，系统使用规则分数并保留原始内容。

## 模型服务接口

模型层使用 DeepSeek OpenAI Chat Completions 兼容接口：

- `DEEPSEEK_API_KEY`
- `DEEPSEEK_BASE_URL=https://api.deepseek.com`
- `DEEPSEEK_MODEL=deepseek-v4-flash`
- `DEEPSEEK_DAILY_LIMIT`

DeepSeek 负责中文翻译、摘要、分类、关键词、重要度和评分理由，并以 JSON 模式输出。未配置密钥时，使用无密钥翻译回退与规则评分，并把翻译结果缓存在数据文件中。密钥只允许存在于本地 `.env` 与 GitHub Actions Secrets。

## 首页与视觉设计

视觉方向为“编辑部头版”：暖米色纸张背景、黑色高对比标题、橙红色强调色，以及衬线标题搭配无衬线界面文字。界面的首要任务是让用户在 30 秒内判断当天最重要的 AI 进展。

桌面首页结构：

1. 品牌、主导航和搜索入口。
2. 日期、最后更新时间和下次更新时间。
3. 今日头条：最重要事件、三句话摘要、评分理由和原文链接。
4. 三条次重要事件。
5. 趋势主题带。
6. 最新动态卡片网格与分类、来源、排序筛选。

移动端改为单列，保持相同信息优先级。

## 交互

- 按重要度或发布时间排序。
- 按模型、产品、商业、研究、政策和其他分类筛选。
- 按来源类型筛选：官方、媒体、论文和社区。
- 标题、摘要、来源和关键词本地搜索。
- 收藏与已读状态保存在浏览器本地，不需要账号。
- 点击新闻跳转原始来源。
- 重复事件展示来源数量，并允许展开所有来源。

## 来源策略

首批来源覆盖 OpenAI、Anthropic、Google DeepMind、Meta AI、Microsoft、NVIDIA、Hugging Face、GitHub、arXiv 和主流科技媒体。来源以配置文件维护，每项包含名称、URL、语言、分类、类型、权威性权重和启用状态。失效来源可以单独关闭，不影响代码。

只保存聚合所需的元数据与短摘要，并始终链接原文，不复制文章全文。

## 可靠性与错误处理

- 每个来源独立超时和重试，失败采用 `allSettled` 语义隔离。
- 单条模型失败保留规则结果，后续运行可重试。
- 每批设置最大新增事件数、模型并发数、每日调用上限和超时。
- 写入前执行 Schema 校验；所有数据在内存中完成并整体替换，避免部分文件损坏。
- 状态文件记录来源成功率、失败信息、处理数量和运行时间。
- 网站在数据陈旧或部分来源失败时显示非阻塞状态提示。

## 测试与验收

自动测试覆盖 RSS 解析、URL 规范化、标题相似度去重、跨来源合并、规则评分、AI 响应校验、无密钥降级、日期分片、索引生成和失败隔离。

最终验证包括：

- 对真实公开 RSS 执行一次抓取。
- 确认生成文件通过 Schema 校验。
- 确认无 API 密钥时仍能生成中文标题与摘要。
- 在桌面和移动视口检查首页。
- 验证搜索、筛选、排序、中英文切换、收藏和已读状态。
- 验证 GitHub Actions 工作流支持定时和手动触发。

## 明确不包含

第一版不包含账号系统、付费订阅、邮件或即时通讯提醒、全文抓取、数据库、原生移动应用和秒级实时推送。这些能力不会阻碍未来扩展。
