# AI 情报仪表盘 UI 改版设计

## 目标

把现有偏杂志排版的 SIGNAL/AI 首页改成更适合高频浏览的中文 AI 情报仪表盘。用户进入页面后，应在数秒内看懂：今天收录了多少条新闻、哪些新闻最重要、数据是否新鲜，以及下一次自动抓取时间。

参考 AI HOT 的清晰信息层级、热点排行和时间流组织方式，但不复制其品牌、页面结构或视觉细节。SIGNAL/AI 继续保留米白、黑色和橙色的编辑部风格，并突出自动抓取状态和“为什么重要”。

## 范围

本次只改造静态前端的结构、样式和展示逻辑，不修改 RSS 抓取、DeepSeek 翻译与评分、去重、JSON 数据格式和 GitHub Actions 调度。

主要涉及：

- `public/index.html`
- `public/styles.css`
- `public/app.js`

不新增框架和第三方前端依赖。

## 信息架构

### 1. 顶部导航

桌面端使用紧凑的吸顶导航栏，包含品牌、主要分类和始终可见的搜索入口。分类保持模型、产品、商业、研究、政策，并显示当前选中状态。

移动端允许分类横向滚动，避免折行或挤压品牌。

### 2. 状态仪表盘

日期条下方增加四个摘要指标：

- 最新收录：当前索引中的新闻总数。
- 重点新闻：重要度达到 80 分的数量；若没有达到 80 分，则显示 70 分以上的数量。
- 最后更新：读取 `status.finishedAt`，展示相对时间，并保留准确日期时间作为辅助文本。
- 下次抓取：按北京时间 01:00、07:00、12:30、19:00 计算最近的下一次执行时间。

若数据陈旧或部分来源失败，继续显示现有状态提醒，并将问题集中放在指标区下方。

### 3. 今日焦点

首屏主内容采用左右双栏：

- 左侧为今日最重要新闻，保留中文标题、摘要、推荐理由、来源、准确发布时间和原文链接。
- 右侧为热点排行，展示接下来 3 条新闻的序号、重要度、标题、来源和发布时间。

主标题尺寸比现版缩小，避免单条新闻占满屏幕。排行用于快速建立当天新闻优先级。

### 4. 分类概览

在焦点区和新闻流之间显示可点击的分类计数按钮，例如“全部 18”“模型 4”“产品 3”。按钮直接复用现有分类筛选状态。

现有趋势关键词保留，但视觉降级为次级横向标签，不与主分类争夺注意力。

### 5. 最新新闻时间流

用单列时间流替换三列卡片网格。每条新闻包含：

- 相对时间与准确发布时间。
- 来源名称和来源类型。
- 分类。
- 重要度标签与数值。
- 中文标题。
- 中文摘要。
- “为什么重要”。
- 收藏、已读和打开原文操作。

重要度分为三档：

- 80–100：重大
- 70–79：值得关注
- 0–69：一般动态

列表默认按重要度排序；用户切换“最新”后按发布时间倒序。新闻原文仍只通过原文链接打开，不在站内复制原文正文。

### 6. 搜索与筛选

搜索框直接显示在新闻流标题区，不再通过图标展开。来源类型和排序选择器保留。所有筛选结果即时更新，并展示当前命中数量。

搜索范围沿用现有标题、摘要、关键词和来源字段。

## 视觉设计

- 保留当前米白纸张背景、深色文字和橙色强调色。
- 使用轻微圆角和浅色分层区分状态指标、焦点和新闻条目。
- 降低超大衬线标题的使用范围；标题仍用衬线字体，数据、标签和操作用无衬线字体。
- 用橙色表示重大新闻，深色表示值得关注，灰色表示一般动态。
- 通过间距、分隔线和对齐建立层级，不依赖大量阴影。
- 悬停效果仅用于可点击区域，并尊重 `prefers-reduced-motion`。

## 响应式行为

### 桌面端

- 页面内容最大宽度约 1280–1360px，居中显示。
- 四个指标横向排列。
- 今日焦点为主新闻与排行双栏。
- 新闻流为单列，时间/分数区域与正文区域形成稳定网格。

### 平板端

- 指标改为两列。
- 今日焦点改为单列，排行横向或两列展示。
- 新闻条目的元数据保持在标题上方。

### 手机端

- 指标为两列紧凑卡片。
- 分类按钮和导航允许横向滚动。
- 新闻条目改为自然纵向排列，摘要和推荐理由不发生横向溢出。
- 搜索、来源和排序控件占满可用宽度。

## 数据与状态处理

界面继续从 `/data/index.json`、`/data/trends.json` 和 `/data/status.json` 加载数据。

- 数据为空时显示明确的首次抓取提示。
- 数据请求失败时显示读取失败信息。
- 部分来源失败时不阻止正常新闻展示。
- 无中文翻译时继续使用现有回退提示，不显示英文正文作为替代内容。
- 相对时间仅作快速识别；所有新闻必须同时提供准确发布时间。

## 可访问性

- 所有筛选、收藏、已读和原文入口使用清晰的中文可访问名称。
- 当前分类使用 `aria-current` 或等价状态表达。
- 时间元素保留标准 `datetime`。
- 键盘焦点具备明显轮廓。
- 颜色不是重要度和状态的唯一表达方式，必须同时显示文字标签。

## 验收标准

- 首屏能看到数据摘要、最重要新闻和热点排行，不需要滚动才能理解当天概况。
- 用户能直接搜索并按分类、来源、重要度或时间筛选新闻。
- 每条新闻清楚显示中文标题、中文摘要、推荐理由、来源、重要度和准确发布时间。
- 桌面端不存在大面积空白或过大的单条标题；手机端不存在横向溢出和控件重叠。
- 收藏、已读、分类筛选、搜索和排序继续正常工作。
- 现有数据抓取测试全部通过，浏览器控制台无页面脚本错误。

## 验证方式

- 运行现有 Node 测试，确保前端改造未影响抓取和数据逻辑。
- 在约 1440px 桌面视口检查首屏层级、筛选和新闻流。
- 在约 390px 手机视口检查导航、指标、控件、新闻条目和横向溢出。
- 手动验证分类、搜索、排序、收藏、已读和原文链接行为。
