# 可靠新闻发现与六个月情报档案设计

## 目标

把“最新新闻没有被及时发现”的问题从单纯增加抓取次数，升级为一套有优先级、有去重、有留档的情报管线：重要模型发布和官方更新先进入候选，论文与高频来源不能挤掉关键事件；同一事件的中英文报道合并；前端可沿时间线、主题和日期快速阅读。

## 方案

1. **来源层**：为来源增加 `priority` 与 `maxItems`。官方博客、厂商更新和精选聚合源优先；arXiv 等高频源每轮限量，避免候选池被淹没；补充 Qwen 官方 GitHub release feed。
2. **选择层**：候选按“重大模型/产品发布 → 官方一手 → 实用教程/观点 → 普通动态”分层，再按重要度、来源优先级和发布时间排序。每轮保留一条重大事件通道，旧一些但重要的发布不会被最新论文挤掉。
3. **去重层**：在标题相似度外识别 Qwen、DeepSeek、GPT、Claude、Gemini 等模型实体和发布信号，合并中英文同事件，并优先保留官方原文链接。
4. **存储层**：保留最近 180 天；按北京时间写入 `data/news/YYYY-MM-DD.json`，同时生成 `data/archive.json` 月份/日期索引。搜索索引仍覆盖全部保留内容。
5. **详情层**：事件写入报道来源时间线和基于公开来源数量/时效的热度估算序列，详情页展示事件全貌、热度走势、报道时间线及原文入口。热度明确标注为估算，不冒充平台真实热度。
6. **导航层**：新增六个月归档和主题地图页面，主题按公司/模型、技术方向、内容形态分组；手机端统一修复 `hidden` 遮罩规则，保证卡片和详情链接可点击。
7. **调度层**：GitHub Actions 改为每 30 分钟运行一次，降低单轮 AI 翻译上限并使用来源限量控制成本；保留手动触发。GitHub cron 仍可能延迟，页面状态会显示实际更新时间。

## 成本与可靠性边界

- 每轮最多处理 12 条新事件、DeepSeek 最多翻译 12 条，保留 180 天数据。
- 高频来源先限量再进入去重，减少网络与模型调用；重要来源不受论文流量影响。
- 热度图是可解释的启发式指标；事实正文和原文链接仍以具体报道为准。
- GitHub Pages 只负责展示，GitHub Actions 负责定时抓取；无法保证云端 cron 零延迟，但 30 分钟频率提供更好的实时性。

## 验收标准

- 同一 Qwen3.8-Max 中英文报道合并为一条事件，并保留官方 Qwen 链接和其他来源。
- 每轮 arXiv 不能占满候选上限，重大模型发布即使发布时间稍早也能进入新事件列表。
- `data/archive.json` 可按最近六个月的月份/日期浏览，旧于 180 天的日文件被清理。
- 详情页出现事件全貌、热度走势、报道时间线；“查看原文”仍跳转原文。
- 手机视口下可点击时间线卡片、详情页和侧边导航，不被遮罩层拦截。
- 测试、构建、GitHub Actions 配置检查通过并成功部署。
