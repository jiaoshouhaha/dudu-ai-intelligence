# 中文新闻详情页设计

## 目标

新闻标题不再直接打开外部网站，而是进入站内中文详情页。只有“查看原文”按钮打开第三方原文。详情页帮助中文读者理解英文新闻，同时避免整篇转载。

## 页面与路由

- 首页标题链接指向 `detail.html?id=<event-id>`。
- `public/detail.html` 是 GitHub Pages 可直接托管的通用详情页面。
- `public/detail.js` 根据查询参数从 `data/index.json` 找到对应新闻并渲染。
- 找不到新闻时展示清晰错误状态和返回首页入口。

## 详情内容

每篇详情包含：

1. 中文标题、中文导语、发布时间和来源。
2. “事情是什么”：基于已抓取文本的详细中文说明。
3. “关键要点”：最多五条事实或结论。
4. “为什么值得关注”：说明实际影响，不重复标题。
5. “对你有什么用”：面向普通用户、开发者或行业从业者给出应用判断。
6. 实用技巧类内容可增加“怎么做”步骤；其他新闻无可靠步骤时不强行生成。
7. 模型、主题、内容类型、证据等级和重要度标签。
8. “查看原文”作为唯一外部跳转入口。

## 数据结构与生成

DeepSeek 对每条新内容生成以下字段：

- `detailZh`: 两到四段中文详细介绍。
- `keyPointsZh`: 两到五条关键要点。
- `impactZh`: 对读者或行业的实际影响。
- `actionStepsZh`: 零到五条可执行步骤。
- `detailCompleteness`: `full`、`summary` 或 `limited`。

模型只能依据输入的标题、Feed/接口正文摘要、来源和发布时间整理，不得补造原文没有的数据。来源材料较短时使用 `limited`，页面提示“基于公开摘要整理”。无 API 或详情生成失败时，详情页使用现有中文摘要、重要性原因和标签组成可读的降级页面。

为控制成本，详情字段与现有中文摘要在同一次 DeepSeek 请求中生成，不增加每篇新闻的 API 请求次数。当前仍在 36 小时展示窗口内的旧新闻会在下一次云端任务中补齐。

## 交互与视觉

详情页复用现有米色纸张、深色侧边栏和橙色强调色。正文宽度收窄以提高阅读舒适度；移动端使用返回按钮和单栏内容。首页点击标题时标记为已读，但不打开外站。

## 可靠性与错误处理

- 渲染前对动态内容做 HTML 转义。
- 查询参数仅用于匹配 ID，不拼接文件路径。
- 外部链接使用 `noopener noreferrer`。
- 数据加载、ID 缺失或记录不存在都有独立错误提示。
- 自动测试覆盖 AI 返回校验、降级字段、站内链接和详情查找。

## 验收标准

- 首页所有新闻标题均进入站内详情页。
- “查看原文”仍打开原始链接。
- 英文来源新闻在详情页显示中文详细介绍。
- 实用技巧新闻显示步骤（有足够依据时）。
- 现有定时抓取、去重、搜索、筛选和部署继续正常。
- 桌面端和移动端均无横向溢出。
